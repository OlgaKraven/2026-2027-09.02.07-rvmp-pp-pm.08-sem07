Конференции.РФ

Создание учебного примера «Конференции.РФ» с пустой папки: модель MySQL, маршруты Python/Flask, шаблоны, дизайн и проверка пользовательского сценария. Весь разбор приведён в методичке; архив готового приложения не предоставляется.

Как превратить задачу в интерфейс

Учебный пример

Создадим «Конференции.РФ» самостоятельно: от пустой папки до страниц выбора площадки, регистрации, заявки, кабинета и администратора. Решение приведено прямо в методичке, отдельный готовый проект не требуется. Стек: Python, Flask, MySQL, HTML, CSS и JavaScript.

Пользователь и главное действие

Организатор хочет найти подходящий зал. На главной объясним назначение сервиса; в каталоге покажем вместимость и оснащение; в заявке дадим понятные поля; в кабинете обозначим состояние. Сначала набросайте каркасы страниц на бумаге: где заголовок, условия выбора, результат и главное действие. Цвет и декор выбираются после этой структуры.

Как работать с кодом

Создавайте указанные файлы самостоятельно. Фрагменты app.py и design.css добавляются сверху вниз в указанном порядке; шаблоны создаются отдельно. Подпись каждого фрагмента указывает место изменения. После законченного этапа проверяйте описанный результат. Полный серверный сценарий нужен для проверки дизайна, но основная цель ПМ.08 — понятный и доступный интерфейс.

Создать структуру своего примера

Спроектировать пользователей и площадки

Связь данных с экраном

Пользователь вводит данные регистрации; площадка отображается карточкой каталога. UNIQUE запрещает повторные логины и почту. Пароль сохраняется только как хеш. В rooms храним характеристики, которые помогают выбрать помещение; category — техническое значение для фильтра.

Начало schema.sql: users и rooms

CREATE TABLE IF NOT EXISTS users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(30) NOT NULL UNIQUE,
  full_name VARCHAR(150) NOT NULL,
  phone VARCHAR(18) NOT NULL,
  email VARCHAR(254) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  is_admin BOOLEAN NOT NULL DEFAULT FALSE
);
CREATE TABLE IF NOT EXISTS rooms (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(150) NOT NULL,
  category VARCHAR(20) NOT NULL,
  city VARCHAR(100) NOT NULL,
  address VARCHAR(200) NOT NULL,
  capacity INT NOT NULL,
  hourly_rate DECIMAL(10,2) NOT NULL,
  image VARCHAR(200) NOT NULL DEFAULT '',
  description TEXT NOT NULL,
  equipment TEXT NOT NULL
);

Проверка структуры

Сопоставьте поля rooms с каркасом карточки: название, тип, город, вместимость, стоимость, описание, оснащение. image пока может быть пустой строкой: позже предусмотрим понятную заглушку.

Связать заявку, пользователя и отзыв

Продолжите schema.sql: applications и reviews

CREATE TABLE IF NOT EXISTS applications (
  id INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  room_id INT NOT NULL,
  event_name VARCHAR(120) NOT NULL,
  event_date DATE NOT NULL,
  event_time CHAR(5) NOT NULL,
  participants INT NOT NULL,
  payment VARCHAR(20) NOT NULL,
  status VARCHAR(40) NOT NULL DEFAULT 'Новая',
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (room_id) REFERENCES rooms(id)
);
CREATE TABLE IF NOT EXISTS reviews (
  id INT PRIMARY KEY AUTO_INCREMENT,
  application_id INT NOT NULL UNIQUE,
  rating INT NOT NULL,
  comment VARCHAR(500) NOT NULL,
  FOREIGN KEY (application_id) REFERENCES applications(id)
);

Почему именно эти связи

user_id и room_id связывают заявку с человеком и залом. FOREIGN KEY не допускает ссылки на отсутствующую запись. status содержит текст состояния. Один отзыв относится к одной заявке: UNIQUE на application_id запрещает повторный отзыв. DATE хранит дату как дату, а не текст.

Границы учебного примера

Заявка не является реальным платежом. Проверка пересекающихся бронирований в этом примере не реализована. Интерфейс должен описывать только фактически работающие действия.

Разбор

Flask(__name__) создаёт приложение. FLASK_SECRET задаётся при запуске и используется для подписи сессии. Path указывает папку текущего файла. TYPES связывает технические категории с русскими подписями, STATUSES задаёт порядок состояний заявки. Пока не запускайте сервер: сначала дополним соединение и главную страницу.

Подключить Python к MySQL

Добавьте в app.py: db

def db():
    if 'db' not in g:
        g.db = pymysql.connect(
            host=os.environ['MYSQL_HOST'], port=int(os.environ['MYSQL_PORT']),
            user=os.environ['MYSQL_USER'], password=os.environ['MYSQL_PASSWORD'],
            database=os.environ['MYSQL_DATABASE'], charset='utf8mb4',
            cursorclass=pymysql.cursors.DictCursor, autocommit=True)
    return g.db

Добавьте в app.py: query

def query(sql, values=(), *, one=False, write=False):
    with db().cursor() as cursor:
        cursor.execute(sql, values)
        if write:
            return cursor.lastrowid
        return cursor.fetchone() if one else cursor.fetchall()

Добавьте в app.py: close_db

@app.teardown_appcontext
def close_db(error):
    connection = g.pop('db', None)
    if connection:
        connection.close()

Почему так

g хранит соединение только в рамках текущего запроса. DictCursor возвращает записи по именам полей. Все значения передаются отдельно от SQL через %s — пользовательский ввод не склеивается с запросом. write=True обозначает изменение данных; one=True — одну запись. teardown закрывает соединение после запроса.

Подготовить сессию и защиту формы

Добавьте в app.py: prepare_request

@app.before_request
def prepare_request():
    session.setdefault('csrf', secrets.token_urlsafe(24))
    g.user = query('SELECT * FROM users WHERE id=%s', (session['user_id'],), one=True) if 'user_id' in session else None
    if request.method == 'POST':
        token = request.form.get('csrf', '')
        if not secrets.compare_digest(token, session['csrf']):
            abort(400, 'Обновите форму: проверка сессии не пройдена.')

Добавьте в app.py: template_context

@app.context_processor
def template_context():
    return {'types': TYPES, 'statuses': STATUSES}

Добавьте в app.py: require_user

def require_user(admin=False):
    if not g.user:
        abort(401)
    if admin and not g.user['is_admin']:
        abort(403)

Связь сервера с интерфейсом

g.user определяет, какие действия доступны в навигации. Случайный csrf-токен передаётся скрытым полем и сравнивается при POST. context_processor передаёт подписи категорий и статусов во все шаблоны. require_user проверяет вход и роль на сервере: скрытая кнопка сама по себе не ограничивает доступ.

Создать команды для учебных данных

Добавьте в app.py: init_db

@app.cli.command('init-db')
def init_db():
    for statement in (ROOT / 'schema.sql').read_text().split(';'):
        if statement.strip():
            query(statement, write=True)
    query('INSERT IGNORE INTO users (username, full_name, phone, email, password_hash, is_admin) VALUES (%s,%s,%s,%s,%s,1)',
          ('Conf2027', 'Учебный Администратор', '8(900)000-00-00', 'admin@example.test', generate_password_hash('Demo77')), write=True)
    click.echo('Таблицы созданы. Учебный администратор: Conf2027 / Demo77.')

Добавьте в app.py: import_rooms

@app.cli.command('import-rooms')
@click.argument('filename', type=click.Path(exists=True, path_type=Path))
def import_rooms(filename):
    rows = json.loads(filename.read_text())
    for room in rows:
        query('INSERT INTO rooms (name,category,city,address,capacity,hourly_rate,image,description,equipment) VALUES (%s,%s,%s,%s,%s,%s,%s,%s,%s)',
              tuple(room[k] for k in ('name','category','city','address','capacity','hourly_rate','image','description','equipment')), write=True)
    click.echo(f'Добавлено помещений: {len(rows)}. Повторный импорт добавит ещё записи.')

Что делают команды

init-db применяет созданный вами schema.sql и добавляет вымышленного администратора. import-rooms читает JSON и добавляет записи в rooms. Команды запускаются явно, поэтому понятно, когда создаются данные. Повторный импорт добавит дубликаты площадок: выполните его один раз в пустой базе. Импорт допускается только для вашего доверенного учебного JSON.

Выбирать площадки по условиям

Добавьте в app.py: rooms

@app.route('/rooms')
def rooms():
    filters = {key: request.args.get(key, '').strip() for key in ('category', 'city', 'capacity')}
    sql, values = 'SELECT * FROM rooms WHERE 1=1', []
    if filters['category'] in TYPES:
        sql += ' AND category=%s'
        values.append(filters['category'])
    if filters['city']:
        sql += ' AND city=%s'
        values.append(filters['city'])
    if filters['capacity'].isdigit():
        sql += ' AND capacity>=%s'
        values.append(int(filters['capacity']))
    rows = query(sql + ' ORDER BY hourly_rate, id', tuple(values))
    return render_template('rooms.html', rooms=rows, filters=filters)

Разбор запроса

Фильтр использует GET: выбранные условия видны в URL. Python добавляет только известные условия, значения передаются параметрами. Сортировка по цене и id даёт предсказуемый порядок. render_template передаёт список rooms и введённые filters в HTML.

@app.route('/register', methods=['GET', 'POST'])
def register():
    values = request.form if request.method == 'POST' else {}
    errors = {}
    if request.method == 'POST':
        rules = {'username': (r'[A-Za-z0-9]{6,30}', 'Латиница и цифры: 6–30 символов.'),
                 'full_name': (r'[А-Яа-яЁё]+(?: [А-Яа-яЁё]+)+', 'Укажите ФИО кириллицей.'),
                 'phone': (r'8\(\d{3}\)\d{3}-\d{2}-\d{2}', 'Формат: 8(XXX)XXX-XX-XX.'),
                 'email': (r'[^\s@]+@[^\s@]+\.[^\s@]+', 'Укажите адрес почты.')}
        for key, (pattern, message) in rules.items():
            if not re.fullmatch(pattern, values.get(key, '')):
                errors[key] = message
        password = values.get('password', '')
        if not 8 <= len(password) <= 128:
            errors['password'] = 'Пароль: от 8 до 128 символов.'
        if values.get('confirm') != password:
            errors['confirm'] = 'Пароли не совпадают.'
        if not errors:
            try:
                query('INSERT INTO users (username,full_name,phone,email,password_hash) VALUES (%s,%s,%s,%s,%s)',
                      tuple(values[k] for k in rules) + (generate_password_hash(password),), write=True)
                return redirect(url_for('login'))
            except pymysql.err.IntegrityError:
                errors['username'] = 'Такой логин или адрес почты уже используется.'
    return render_template('register.html', values=values, errors=errors)

Разбор

Правила проверяют каждое поле и заполняют словарь errors. Пароль должен иметь 8–128 символов, подтверждение совпасть. INSERT выполняется только при отсутствии ошибок; пароль хешируется. Уникальность окончательно проверяет MySQL. При ошибке снова выводим форму с values и errors, при успехе перенаправляем на вход.

@app.route('/apply/<int:room_id>', methods=['GET', 'POST'])
def apply(room_id):
    require_user()
    room = query('SELECT * FROM rooms WHERE id=%s', (room_id,), one=True)
    if not room:
        abort(404)
    values, errors = request.form if request.method == 'POST' else {}, {}
    if request.method == 'POST':
        if not 3 <= len(values.get('event_name', '').strip()) <= 120:
            errors['event_name'] = 'Название: 3–120 символов.'
        try:
            if date.fromisoformat(values.get('event_date', '')) < date.today():
                raise ValueError
        except ValueError:
            errors['event_date'] = 'Укажите сегодняшнюю или будущую дату.'
        if not re.fullmatch(r'(?:[01]\d|2[0-3]):[0-5]\d', values.get('event_time', '')):
            errors['event_time'] = 'Укажите время.'
        if not values.get('participants', '').isdigit() or not 1 <= int(values.get('participants', '0')) <= room['capacity']:
            errors['participants'] = 'Число участников должно соответствовать вместимости.'
        if values.get('payment') not in ('Карта', 'СБП', 'Наличные'):
            errors['payment'] = 'Выберите способ оплаты.'
        if not errors:
            query('INSERT INTO applications (user_id,room_id,event_name,event_date,event_time,participants,payment) VALUES (%s,%s,%s,%s,%s,%s,%s)',
                  (g.user['id'], room_id, values['event_name'].strip(), values['event_date'], values['event_time'], int(values['participants']), values['payment']), write=True)
            return redirect(url_for('dashboard'))
    return render_template('apply.html', room=room, values=values, errors=errors)

Что обеспечивает сервер

room_id определяет площадку и её вместимость. Проверяем название, дату, время, число участников и оплату; чужой user_id из формы не принимаем, используем g.user.id. При ошибке возвращаем форму с объяснением, при успехе показываем кабинет. Оплата — значение заявки, реального платежа нет.

@app.post('/review/<int:application_id>')
def review(application_id):
    require_user()
    row = query('SELECT * FROM applications WHERE id=%s AND user_id=%s', (application_id, g.user['id']), one=True)
    if not row:
        abort(404)
    rating, comment = request.form.get('rating', ''), request.form.get('comment', '').strip()
    if row['status'] != 'Завершено' or rating not in ('1','2','3','4','5') or not 1 <= len(comment) <= 500:
        abort(400, 'Отзыв: завершённая своя заявка, оценка 1–5 и текст 1–500 символов.')
    try:
        query('INSERT INTO reviews (application_id,rating,comment) VALUES (%s,%s,%s)', (application_id, int(rating), comment), write=True)
    except pymysql.err.IntegrityError:
        abort(400, 'Отзыв уже оставлен.')
    return redirect(url_for('dashboard'))

Проверка условий

Запрос ищет одновременно id заявки и id пользователя. Чужая заявка не найдётся. Сервер проверяет завершённый статус, оценку 1–5 и длину текста. UNIQUE в reviews исключает повторный отзыв даже при повторной отправке.

Добавить подсказку заполнения формы

Создайте static/design.js: первая часть

// ПМ.08: подсказка сопровождает основную форму, сервер проверяет данные.
'use strict';
const designForm = document.querySelector('.stack-form');
if (designForm) {
  const allFields = [...designForm.querySelectorAll('input, select, textarea')];
  const fields = allFields.filter((field, index) => field.type !== 'hidden' && field.required
    && (field.type !== 'radio' || allFields.findIndex(other => other.name === field.name) === index));
  const summary = document.createElement('p');
  summary.className = 'design-summary';
  summary.setAttribute('role', 'status');
  const heading = document.createElement('strong');
  heading.textContent = 'Заполнение формы';
  const counter = document.createElement('span');
  summary.append(heading, counter);
  designForm.prepend(summary);
  function updateSummary() {
    const filled = fields.filter(field => field.type === 'radio'
      ? allFields.some(other => other.name === field.name && other.checked)
      : field.value.trim() !== '').length;
    counter.textContent = `Заполнено ${filled} из ${fields.length} обязательных полей. Проверка выполняется при отправке.`;
  }
  designForm.addEventListener('input', updateSummary);
  designForm.addEventListener('change', updateSummary);
  updateSummary();
}

Разбор

Выбираем .stack-form, отбираем обязательные поля, исключаем скрытый csrf. Создаём подсказку через textContent и обновляем на input/change. Счётчик сообщает факт заполнения, а не правильность данных; окончательно проверяет Python. Работа с группами radio оставлена как приём для самостоятельного варианта.

Проверка

Связать сообщение ошибки с полем

Продолжите static/design.js: вторая часть

// Связываем видимые серверные ошибки с соответствующими полями.
const errors = document.querySelectorAll('.field-error');
let firstInvalid = null;
errors.forEach((error, index) => {
  if (!error.id) error.id = `design-error-${index}`;
  const group = error.closest('.field');
  // Поле и его ошибка находятся внутри одной группы .field.
  const input = group ? group.querySelector('input, select, textarea') : null;
  if (!input || !input.matches('input, select, textarea')) return;
  input.setAttribute('aria-invalid', 'true');
  const ids = new Set((input.getAttribute('aria-describedby') || '').split(/\s+/).filter(Boolean));
  ids.add(error.id);
  input.setAttribute('aria-describedby', [...ids].join(' '));
  firstInvalid ||= input;
});
if (firstInvalid) firstInvalid.focus();

Разбор

Находим сообщения .field-error, выбираем поле внутри .field. aria-invalid указывает ошибочный ввод. aria-describedby дополняется идентификатором ошибки, существующая подсказка сохраняется. Фокус ставим только после ответа с ошибками, а не при каждом символе.

Проверка

Пустая регистрация: фокус в логине, текст ошибки рядом с полем, счётчик 0 из 6. Исправьте ввод и отправьте снова.

TemplateNotFound: проверьте имя созданного шаблона и папку templates. BuildError: сопоставьте имя функции маршрута и url_for. Соединение MySQL: проверьте переменные и запущенный сервер. CSS 404: файл должен быть static/design.css. Не повторяйте импорт в заполненную базу ради обновления внешнего вида.
